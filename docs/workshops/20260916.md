## SPECS.md §1 — Required sections (draft): transform / morphing references

We are defining `transform` / `morphing` and they use some references
(e.g. `hr_1` for the hinge line of the rudder, `ha_1` for the hinge line
of the aileron).

Those references must exist in the JSON, and we must verify their
existence and fail early if they do not exist.

The definition of this entity must live inside the `geometry` block,
sub-block `transformation_vector`, and each item is composed of a point
and a direction (e.g. vector at the origin pointing +x:
`"ha_1": [[0,0,0],[1,0,0]]`).

To make the engineer's life easier, the relations below can be used
(hard-coded):

- none = [0,0,0]
- x = [1,0,0]
- y = [0,1,0]
- z = [0,0,1]
- xy = [1,1,0]
- xz = [1,0,1]
- yz = [0,1,1]
- xyz = [1,1,1]

Valid YAML example for the transformations block:

```yaml
geometry:
  transformation_vector:
    ha_1: [[5,6,7],[0,1,0]]
    3d: [None,xyz]
    yz: [[0,0,0],yz]
    y: [[0,0,0],y]
  transformation_groups:
    RUDDER: ['V\.RUD.*']
    AILERON: ['W\.AIL.*_LH']
control_surfaces:
  transform: {'RUDDER': ['t:y:20', 's:3d:50'], 'AILERON': ['r:ha_1:20'], … }
  morphing: {'AILERON': ['r:ha_1:20'], 'WING_TIP': ['t:y:50'], … }
```

```yaml
geometry:

    AIRCRAFT:
    - SREF:  2.231
      CREF:  0.500

      XREF:  1.598

```

## Mesh generation process

The proposed file structure is `./01-GRIDS` with the sub-folders `GEOM`
(holding all geometries common to the simulation campaign),
`BATCH_SCENARIO` (with the ANSA batch-scenario files containing the
instructions on how to generate the mesh) and `GRIDS` holding the mesh
generation results, intermediate files, mesh generation logs, and a
`lock` to avoid collisions between multiple users generating meshes.
