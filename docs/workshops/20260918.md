## Backend and frontend

The refactoring is divided into a backend and a later frontend. JSON is
the interface. Current work starts at JSON and continues through meshing,
Fluent input generation, PBS execution and post-processing. The matrix
and REF, if retained, are frontend inputs before that boundary. The backend
receives reference quantities such as CREF through JSON and performs flow
calculations, including resolving conditions when Reynolds number is
specified instead of altitude.

Meshing parameters and geometry references are in JSON. Keep the current
ANSA script and its YAML interface until that script is refactored later.
ANSA already handles transformations and morphing.

## Examples and source dependencies

- POLAR 002: alpha -10 to +20 degrees by 1, beta 0, Mach 0.2, altitude 0 ft.
  Its grid is generated using the current YAML/ANSA route.
- POLAR 003: beta 0 to 15 degrees by 1, alpha 0. Its first point starts
  from POLAR 002's saved alpha 0 solution. No new grid is generated.
- POLAR 003 waits for the required alpha 0 solution to be available;
  it does not depend on completion of the entire POLAR 002 sweep.

The three-digit polar names above describe the legacy example. They do
not decide a change to the existing backend POL identity requirement.

## Confirmed alpha branch sequence

Within one Fluent session:

1. Solve alpha 0 for its specified iterations and save the solution.
2. Update far-field direction and run +1, +2, …, +20 in succession.
3. Reload the saved alpha 0 solution.
4. Update far-field direction and run -1, -2, …, -10 in succession.

Each point within a branch starts from the current solution. Fluent is
not closed between points or branches. Reloading zero is not a second
iteration run at zero.

## Iterations and convergence

The owner confirmed that every point runs its full specified number of
iterations. Convergence checking and the definition of convergence are
deferred. There is no convergence-based early advance or gate on later
points in the current phase. Completing iterations is not an assessment
of physical convergence.

## UDF and post-processing

- Populate existing UDF `.c` templates with case-specific values.
- A dedicated post-processing script generates the ADF with the six
  force/moment coefficients in body, wind and stability axes.
- Flow figures, Cp and load distributions are optional.

## Still open

Exact JSON fields, general sweep ordering beyond the confirmed example,
the per-point iteration representation/legacy KNITERS mapping, saved-file
readiness and compatibility, and ANSA/post-processing invocation contracts
remain to be specified. Continuing iterations at an interrupted point is
separate from the confirmed new-polar initialization workflow.
